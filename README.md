# 机械臂视觉抓取工作区

JAKA 机械臂、Z-EFG-20P 夹具和 Inuitive NU4000 深度相机的控制、识别与抓取程序。

## 常用入口

在 `启动入口/` 目录双击以下脚本：

| 功能 | 启动文件 |
| --- | --- |
| 图形化 3D 抓取软件 | [启动3D抓取软件.bat](启动入口/启动3D抓取软件.bat) |
| 彩色 / 深度相机预览 | [start_color_depth_viewer.bat](启动入口/start_color_depth_viewer.bat) |
| 双夹爪控制台 | [启动夹具控制台.bat](启动入口/启动夹具控制台.bat) |
| 松开机器人夹爪（20 mm） | [松开夹具.bat](启动入口/松开夹具.bat) |
| 机器人夹爪设到 8.88 mm | [夹具到8.88mm.bat](启动入口/夹具到8.88mm.bat) |
| 回到保存的 Home | [一键回Home.bat](启动入口/一键回Home.bat) |
| 回到“卡片定位”点 | [卡片定位.bat](启动入口/卡片定位.bat) |
| 卡片上料对准、开合夹爪后到卡片定位 | [卡片上料对准.bat](启动入口/卡片上料对准.bat) |

| 一键取后继续流氓三步 | [一键取加流氓.BAT](启动入口/一键取加流氓.BAT) |
| 一键视觉抓取 | [一键视觉抓取.bat](启动入口/一键视觉抓取.bat) |
| 命令行 3D 识别预览 | [启动3D识别抓取.bat](启动入口/启动3D识别抓取.bat) |

Home 保存在 [robot_poses.json](robot_poses.json) 的 `home` 中，以文件内的数值为准。回位流程先只动 J3，让 TCP Z 升高到 `first_lift_z`（当前 340 mm），再对位到 Home 上方，最后下降到 Home；已到 Home 时直接结束。若单独移动 J3 无法达到抬升高度，则停止并报告错误。J3 的旋转方向根据当前姿态计算。

`流氓.BAT` 按 `liumang.steps` 执行：启动时先按现有要求抬升，随后到原“流氓”点（第一步），再到新增的中间点 `liumang_step2`（第二步），最后到原第二步 `liumang_step3`（第三步）；各步之间直接进行关节运动，不插入额外抬升。任一步失败即停止后续动作。

`一键取加流氓.BAT` 连续执行“一键取 → 流氓 → 松开夹具”：先按需要仅动 J3 抬升到 340 mm，再到上料处；到上料处后再次按需抬升，再依次走流氓第一、二、三步。两段运动共用一次控制端口锁与速度倍率设置，运动期间保持夹爪原状态；全部到位成功后调用 `松开夹具.bat`，张开至 20 mm。任一步失败即停止后续动作，不执行末尾松开。加 `--check` 可离线查看运动顺序，不连接或操作夹具。

关节到位判定同时要求：绝对关节误差不超过 0.5°、TCP 位置各分量误差不超过 3 mm、姿态分量误差不超过 1°，并稳定 0.1 秒，每 0.05 秒轮询一次。所有示教点使用关节速度 180°/s、加速度 720°/s²、速度倍率 100%。控制器停止但持续 3 秒不满足条件时立即报告具体误差；执行记录逐步保存在 `logs/return_pose_loading_then_liumang.json` 的 `completed_steps` 中。

“上料处”单独保存在同文件的 `loading` 中，关节角 `J1～J6 = [0, 0, -90, 0, -90, 0]°`。

“卡片定位”保存在 `robot_poses.json` 的 `card_position` 中。双击 `卡片定位.bat`，先按需仅动 J3 抬升到配置高度 340 mm，再到保存的关节姿态，保持夹爪当前状态；已在该点时直接结束。运行 `卡片定位.bat --check` 仅离线检查配置。

“卡片上料对准”保存在 `robot_poses.json` 的 `card_loading_align` 中。双击 `卡片上料对准.bat`：第一步将夹爪全开至 20 mm，等待 1 秒；再仅动 J3，将 TCP 升至配置高度 340 mm（已更高时沿用当前高度）；再到目标仅动 J3 抬高后的姿态，完成高处对位；最后仅动 J3 回落到保存的上料点。下降为 J3 单轴弧线，并非 TCP 竖直直线。即使启动时已在上料点，也先执行抬升流程。机械臂启动前按关节插值不超过 1° 采样检查高处对位路径，若会提前低于净空高度则不发出机械臂动作；运行中高处对位下降超过 2 mm 则停止。上料点确认到位后夹爪收到 5.96 mm，等待 1 秒，最后调用 `卡片定位.bat`。夹爪回读的是设定值，等待不代表测量到实际开度。打开夹爪失败、抬升不可达、未升到高度或其他任一步报错，均取消后续步骤。加 `--check` 可离线检查整个顺序，不移动机械臂或夹爪。

“卡片下料”单独保存在 `robot_poses.json` 的 `card_unloading` 中，本次记录与“卡片上料对准”坐标相同。双击 `卡片下料.bat`：先按现有仅动 J3 抬升的规则到该点，确认到位后全开夹爪至 20 mm，等待 2 秒并核对设定值回读，然后调用 `一键回Home.bat`，沿用回 Home 的先抬升流程。任一步失败则取消后续步骤。加 `--check` 仅离线检查下料点和夹爪参数并显示最后回 Home 的步骤，不等待、不调用实际回 Home 脚本。

`左右舞动1分钟.bat` 以启动时的位置为中心，左右各约 200 mm，约 60 秒平滑往返最多 9 次并回到启动姿态。默认根据当前位置从 9 次逐档降低，选择 TCP、姿态和采样关节速度及加速度均通过校核的最快节奏；调整时会显示通过的次数，时长和摆幅不变，所有候选都无法通过时不启动。实际到位较慢时，根据已观测的最长单段耗时预留下一次出发和回中的时间；剩余时间不足时，在中心结束往返并等待至 60 秒，最终输出实际完成次数。原 `左右舞动20秒.bat` 也使用同样的 1 分钟设置。TCP 加速度设为 400 mm/s²；速度根据各段长度和节拍计算，上限仍为 250 mm/s。左右端点相对启动角度采用 J4 ±20°、J5 向当前弯曲方向配合 15°、J6 反向 ±30°，经过中间位置时回腕；沿途关节随等高 TCP 路径协调运动，实际极值可能比端点变化更大。端点先通过 J3 在 15° 内补偿高度，再用 MoveL 执行 Z 固定的平面轨迹，其他关节随逆解补偿。不再自动缩小腕部幅度。

两个舞动 BAT 入口都会先调用 `卡片定位.bat`，定位成功后再读取实际姿态、规划并开始舞动，结束回到舞动开始时的姿态。定位失败不启动舞动；1 分钟计时不包含前面的定位和规划。加 `--check`、`--plan` 或帮助参数时，前置卡片定位只执行离线检查；`--plan` 校核当前实际姿态的轨迹，不移动到卡片点。直接运行 `horizontal_sway.py` 仍从当前姿态规划，不包含前置定位。

每段确认到位后等待下一拍再发动作；若实际到位落后于目标节拍，则从该段实际开始计时，避免延迟不断挤占后续动作时间。单段超时为目标节拍长度加 0.35 秒，已空闲且六轴与 TCP 全部达标的迟到反馈最多额外接受 0.1 秒；全程到位宽限不超过 0.5 秒（通信阻塞、停止验证耗时另计）。持续不到位或剩余时间不足以安全发出后续动作时停止，不提高速度追赶。`logs/horizontal_sway.json` 记录每段发令、应答、到位时间、实际完成段数，以及最后反馈的六轴、TCP、空闲状态和误差，便于判断延迟原因。

规划器按不超过 2.5 mm 位移、1° 姿态变化的间距检查整段路径的连续逆解、正解高度和关节范围，拒绝关节跳转或到达不同圈数；采样估计关节速度及加速度，分别限制为 120°/s、600°/s²。规划高度误差要求不超过 0.1 mm。运行中高度偏离超过 1 mm、TCP 偏离当前线段超过 2 mm、关节超出该段校核范围、报错或未按时到位则停止；六轴和 TCP 均到位才报告完成。不执行首段抬升，不操作夹爪，运动学检查不包含障碍物净空。`--check` 仅离线检查，`--plan` 只读校核当前轨迹；可用 `--amplitude-mm 100` 减小左右位移，或 `--cycles 1` 手动放慢节奏。手动指定次数时按该节奏严格校核，不通过则停止；自动模式只调整节奏，不缩小摆腕幅度，也不把关节跳转、超限或不可达误当成速度问题重试。按 Ctrl+C 中止时停止当前位置，不追加回中动作。

`一键视觉抓取.bat` 的流程为：从 Home 出发 → 到上料处/料框 → 彩色和深度视觉选择零件 → 夹爪全开至 20 mm → 对准细管抓点的位置、高度和方向 → 收至 8.65 mm → 提起退出料框 → 保持夹持回 Home。提起后的复核图保存在 `pick_results/after_grasp/`。启动时必须已在 Home；没有有效抓点时停止，不继续执行闭合。

“下料区”单独保存在同文件的 `unloading` 中，关节角 `J1～J6 = [90, 45, 45, 0, 45, 0]°`。

## 目录与配置

| 位置 | 内容 |
| --- | --- |
| 根目录 `*.py` | 运行中的应用、机械臂 / 夹具控制、相机采集和算法模块 |
| `robot_poses.json` | Home、Home 上方对位关节、首段抬升高度、上料处、下料区和拍照点 |
| `pick_place_config.json` | 相机标定、模型匹配、抓取及放置参数 |
| `gripper_devices.json` | 当前夹爪设备及 IO 配置 |
| `model.FCStd`、`螺栓.FCStd` | CAD 模型；两个文件内容相同，分别保留供测试和当前配置使用 |
| [docs/](docs/) | 操作与标定说明 |
| [diagnostics/](diagnostics/) | 设备发现记录、历史 IO 映射与安装诊断日志 |
| [installers/](installers/) | JAKA 安装包 |
| `calibration_data/` | 标定采集、轨迹和求解结果 |
| `pick_results/` | 点云、匹配候选、抓取方案及执行报告 |
| `logs/` | 程序运行日志 |
| `tests/` | 自动化测试 |
| `JAKA/` | 厂商原始 SDK 和示例 |
| `.runtime/` | 桌面软件和夹具控制运行环境 |
| `.camera-runtime/` | 相机 SDK 和 3D 算法运行环境 |
| `.driver-setup/`、`.runtime-setup/` | 驱动及运行环境安装、诊断资料 |

BAT launchers are now in `启动入口/`; historical pose backups are in `backups/robot_poses/`. Programs, active configuration, models, runtimes and generated data retain their existing paths.

## 本地检查

以下命令仅运行离线测试：

```powershell
python -m unittest tests.test_arm_control -v
.\.camera-runtime\python.exe -m unittest discover -s tests -p "test_*.py" -v
```

完整测试需要 3D 依赖及支持 Tkinter 的运行环境。`.camera-runtime` 用于相机和 3D 算法；桌面界面测试可单独使用 `.runtime` 运行。缺少桌面环境时，可使用根目录 `setup-runtime.ps1` 安装。
