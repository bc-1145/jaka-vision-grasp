# JAKA / Z-EFG-20P 双夹爪控制台

本文中的启动文件、配置及命令路径均相对于工作区根目录（本文件的上一级）。[返回工作区入口](../README.md)。

使用同目录 `arm_control.py` 的协议和参数，通过机器人 TCP 10001 端口控制夹具。`gripper_transport.py` 负责复用 TCP 长连接，原 SDK 保持原样，无需加载 `JAKA/jkrc.pyd` 或运行 `JAKA/test.py`。

## 启动

需要安装包含 Tkinter 的 Python 3.10 或以上版本（Windows 官方 Python 安装包包含 Tkinter），无需 pip 依赖。

若同目录已有 `.runtime`，启动脚本会优先使用其中的 Python，无需配置系统 PATH。缺少运行环境时可运行 `powershell -ExecutionPolicy Bypass -File setup-runtime.ps1`，从 Python 官方下载并校验安装包签名，再安装到本目录 `.runtime`。这会注册当前用户的 Python 安装，不修改 PATH 或文件关联。

双击 `启动夹具控制台.bat`，或在此目录运行：

```powershell
python gripper_app.py
```

使用 `python gripper_app.py --connect` 可在窗口打开后自动进行只读连接，真机动作仍需在界面中勾选许可后滑动滑块或点击按钮。

## 真机操作

已从当前控制器的扩展 IO 配置识别出以下两只夹爪，并保存到 `gripper_devices.json`：

| 界面标签 | 从站 ID | 位置高/低字输出 | 机器人地址 |
| --- | --- | --- | --- |
| 机器人夹爪 | 1 | 3 / 4 | 10.5.5.100 |
| 定位夹爪 | 2 | 23 / 24 | 10.5.5.100 |

窗口顶部有两个标签页，切换后操作对应夹爪。两页的目标开度、实时滑块、许可、状态和日志各自独立。切换标签会清除离开页尚未发送的滑动目标。两只夹爪共用一个控制器，程序会将整次写入和回读串行执行，避免多线程交叉写入。

1. 选择要控制的夹爪标签。默认选择「真机」，填写机器人地址，SDK 中默认地址为 `10.5.5.100`。电脑需要能够访问机器人 TCP 10001、10000 端口。
2. 在对应页面点击「连接」。此时只核对设备 ID、映射和读取该夹爪的位置输出，不发送开合、上电、使能或机械臂运动指令。
3. 确认现场可以操作夹具后，勾选「允许本次连接发送真机夹具指令」。每次重新连接都需要重新勾选。
4. 默认开启「滑动实时发送」，拖动 0～20 mm 滑块即可连续控制开合；点击「全开」发送 20 mm，点击「闭合」发送 0 mm。也可输入毫米数，按回车或点击「发送目标开度」。输入数字本身不发送指令。取消「滑动实时发送」后，滑块只修改目标，需点击发送。
5. 查看回读与日志。默认每 2 秒在空闲时读取状态，通信在后台执行，界面不会因网络等待冻结。

两只夹爪共用一个 TCP 长连接，避免每次读取或写入都重新建立连接。只读请求遇到通信异常会更换连接重试一次；仍失败时，界面按 1、2、4、8、15 秒间隔自动重新连接（后续最多每 15 秒一次），核对设备映射并恢复状态读取。断线后清除待发送目标和操作许可，恢复后需重新勾选许可，不会自动重发旧开度。点击「断开」可取消自动重连。

连接、重连及通信异常会保存到程序目录的 `logs/gripper.log`，日志达到约 2 MB 后轮转，保留三份历史文件。写入结果未确认时仍需手动重新连接，详见下面的限制。

如 JAKA 报 `0x0F0056 扩展 IO 模块未运行`，需在机械臂静止、队列为空时先下使能，在 JAKA「I/O 面板」中点击扩展 IO「运行」，确认运行后恢复机器人使能。当前现场控制器实测 `extio.mode=1` 为运行、`0` 为编辑/停止；停止时仍可读到旧的输出缓存，不能据此判断夹爪可用。程序在连接和写入前检查此状态，不会自动切换总线或机械臂使能。

后台刷新仅因控制端口被其他程序占用而失败时，清除待发送目标，保留已建立连接和操作许可，空闲后继续读取。首次连接遇到端口忙会只读重连，不会误显示连接成功或重发旧目标。

模拟模式无需连接设备，可验证界面和操作流程；模拟时不调用任何网络接口。

## 接口约定与限制

- 第一只夹爪使用 SDK 的扩展输出 3、4，第二只使用从真机扩展 IO 的 `setup`、`pinmap` 推导并回读验证的 23、24。它们分别为夹持位置的高、低 16 位字。毫米目标按 float32 编码，先写对应高字，再写低字（任意开度的低字可能非零）。按钮发送等待 0.3 秒后回读，实时滑动及 BAT 指令立即开始回读。总线回读尚未更新时，在最多 2 秒的确认窗口内仅重复读取，匹配即返回；每次读取仍受通信超时约束。没有自动写入重试。
- 每次连接和每次真机写入前会重新核对控制器配置中的扩展设备标识、从站 ID 和位置映射；映射变化则拒绝动作。第二只夹爪的映射来自第一只设备占用的 20 个输出通道偏移，不能假定是 5、6。
- 实时滑动的发送间隔至少 120 ms（最多约 8 次/秒，实际速度受网络响应影响）。同时最多一项通信在执行，期间滑块继续响应，只保留最新目标，不累计中间位置；停手后仍会发送最后一次有效目标。关闭实时发送、撤销许可、断开、退出或发生通信异常会清除待发送目标。已经发出的指令无法通过界面取消。
- 厂家协议中夹持位置为 0～20 mm 的 float32。20 mm 编码为 `0x41A00000`，高字为 `16800`、低字为 `0`，与原 SDK 全开值一致；10 mm 为 `16672 / 0`，12.34 mm 为 `16709 / 28836`。原始高字与毫米数并非线性比例。界面显示目标毫米数、百分比，以及两个输出寄存器解码后的设定毫米数；它们不是标定过的夹指实际间距。
- 回读是输出寄存器设定，不是夹具位置传感器，也不代表夹持成功。SDK 没有提供夹持力、速度、夹持检测或停止夹具的接口。
- 每次真机写入前读取 `get_motion_state`，如 SDK 报告急停、碰撞或软限位，则拒绝写入。这不替代设备原有安全机制。
- 两个寄存器分次写入，不具备原子性。写入或后续回读失败时，夹具可能已经动作；程序提示结果未确认、解除操作许可并停止轮询，需检查现场并重新连接回读后再决定下一步。
- 「断开」或退出软件不会松开、停止夹具，也不会改变机械臂状态。关闭时若正在通信，界面会等待本次操作返回后退出。现场停止使用实体急停。
- 界面只控制夹具，不包含机械臂移动功能。

协议依据：[慧灵 Z-EFG-20P 厂家手册，第 5～6 页](https://cn.hitbot.cc/hitbot/document/Z-EFG/Z-EFG-20P/Z-EFG-20P.pdf)。继续使用本机 SDK 已知的扩展 IO 映射，不对未映射的 Modbus 反馈、速度或电流寄存器发送命令。

重新识别控制器和保存真实映射：

```powershell
.\.runtime\python.exe gripper_discovery.py --subnet 10.5.5.0/24 --save-config
```

该工具只探测指定机器人网段的 TCP 10001 端口、读取状态和映射，不发送任何夹爪写入指令。保存后重新打开控制台。`--inspect` 可另外将只读诊断结果保存到 `diagnostics/device_discovery.json`。
